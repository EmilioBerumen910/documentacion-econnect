S3

Resumen de qué hace en Econnect

S3 concentra frontend estático, descargas, integraciones SFTP, datos productivos, logs, despliegues y piezas ya orientadas a migración hacia mx-central-1.

Arquitectura / flujo

S3 soporta al menos cuatro patrones:

  1. frontend estático detrás de CloudFront,
  2. integraciones documentales/SFTP,
  3. almacenamiento productivo,
  4. replicación regional hacia mx-central-1.

Riesgos y gaps

  • Replicación deshabilitada en buckets que parecen importantes.
  • Predomina SSE-S3 en vez de SSE-KMS.
  • Muchos buckets con versioning Suspended o Not Configured.
  • No se evidenció Public Access Block por bucket.
  • El mapa real de acceso por IAM a 22 buckets sigue abierto.

Runbook operativo

  1. Identificar bucket afectado y su función.
  2. Confirmar versioning, cifrado y replicación.
  3. Revisar bucket policy y access path.
  4. Confirmar si el problema es de origen, replicación o consumidor.
  5. Para frontends, revisar también CloudFront.

Checklist de migración a mx-central-1

  1. Priorizar buckets críticos.
  2. Confirmar CRR activa donde aplique.
  3. Completar PAB y lifecycle por bucket.
  4. Migrar o replicar KMS si se usa SSE-KMS.
  5. Validar consumidores de frontend y de integración.
  6. Hacer pruebas de lectura/escritura en la región destino.

Cómo validar

aws s3api list-buckets
aws s3api get-bucket-versioning --bucket econnectpro.mx
aws s3api get-bucket-replication --bucket production.econnect.ds
aws s3api get-bucket-encryption --bucket ecnc-prod-s3-mx1-manifest --region mx-central-1

Cómo obtener la evidencia

aws s3api get-bucket-policy --bucket econnectpro.mx
aws s3api get-public-access-block --bucket econnectpro.mx
aws s3api get-bucket-lifecycle-configuration --bucket econnectpro.mx
aws s3api get-bucket-notification-configuration --bucket sftp.econnectpro.mx
