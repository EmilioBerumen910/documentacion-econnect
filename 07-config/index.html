Configuración externa (SSM/Secrets)

Fuente: assets/EC2-Documentacion-Econnect.pdf
Generado: 2026-03-03

Fuente de configuración y secrets

En us-east-1, la evidencia apunta a que los secrets/config se gestionan principalmente mediante:

  • AWS Systems Manager Parameter Store (SSM Parameter Store)
    Las instancias usan el rol AmazonSSMRoleForInstancesQuickSetup con permisos (vía policies como AmazonSSMManagedInstanceCore y políticas de CloudWatch Agent) que habilitan ssm:GetParameter / ssm:GetParameters. Esto permite leer parámetros y secretos (p.ej. SecureString).

AWS Secrets Manager

No se identificaron roles de EC2 con permisos explícitos a Secrets Manager (p.ej. secretsmanager:GetSecretValue) con la evidencia disponible.

Implicaciones y pendientes

  • Pendiente: inventariar nombres y paths de parámetros SSM usados por cada aplicación/rol (para migración y rotación de secrets).
  • Recomendación: si la organización estandariza Secrets Manager, evaluar migrar secretos críticos o documentar claramente el esquema actual en SSM (naming, KMS key, rotación).
