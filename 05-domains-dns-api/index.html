Dominios y DNS

Dominios identificados

Se evidenciaron dos custom domains principales:

Dominio Tipo API mapeada Stage
api.econnectpro.mx EDGE apieconnectpro test
socket.econnectpro.mx REGIONAL api_socket test

Arquitectura actual de publicación

api.econnectpro.mx

  • usa custom domain EDGE
  • implica CloudFront administrado por API Gateway
  • target visible:
  • da3va61kxw5mp.cloudfront.net

socket.econnectpro.mx

  • usa custom domain REGIONAL
  • apunta directamente al endpoint regional de API Gateway
  • target visible:
  • d-tw5pnm947f.execute-api.us-east-1.amazonaws.com

Certificado ACM

Ambos dominios usan el mismo certificado ACM en us-east-1.

CloudFront y edge behavior

Evidencia confirmada

  • api.econnectpro.mx sí está detrás de CloudFront debido a su tipo EDGE.
  • socket.econnectpro.mx no está detrás de CloudFront; es un endpoint regional directo.

Riesgos

  • comportamiento distinto de propagación
  • comportamiento distinto de caché
  • estrategias de rollback diferentes
  • necesidad de validar certificados y mappings por separado

Observación crítica

El dominio api.econnectpro.mx está mapeado al stage test.
Antes de migrar debe aclararse si:

  • test es realmente el stage productivo, o
  • existe un naming legacy que no refleja el ambiente real.

Estrategia de cutover recomendada

Recomendación principal

Usar cambio de API mapping / base path mapping en API Gateway como mecanismo principal de cutover.

Motivos

  • es más rápido
  • es más reversible
  • evita un cambio DNS más grueso
  • encaja con la arquitectura actual de custom domains

Cuándo usar DNS

Solo cuando cambie la estrategia de publicación o el dominio deba apuntar a un target completamente distinto.

Rollback

Recomendación

Rollback por reversión del mapping del custom domain.

Tiempos objetivo inferidos

  • rollback por mapping: inmediato / < 30 s
  • rollback por DNS ALIAS: 60–300 s aprox.

Qué debe recrearse en región destino

Para api.econnectpro.mx

  • custom domain compatible
  • certificado en la región correcta según tipo EDGE/REGIONAL
  • mapping a la API destino
  • pruebas de resolución y handshake TLS

Para socket.econnectpro.mx

  • custom domain regional
  • certificado asociado
  • mapping a WebSocket API destino
  • prueba de conexión WebSocket real

Riesgos de migración

  1. Certificado centralizado

  2. un error o expiración afecta ambos dominios

  3. EDGE vs REGIONAL

  4. requieren validaciones distintas y pueden reaccionar distinto al cutover

  5. Alias sin weighted/failover

  6. el cambio es binario; no existe una transición gradual documentada

  7. Stage ambiguo

  8. el dominio principal apunta a test, lo que obliga a validar semántica antes del cambio

Recomendaciones operativas

  • congelar cambios de domain mapping durante la ventana de migración
  • guardar estado “before” exacto:
  • dominio
  • API ID
  • stage
  • endpoint type
  • target
  • validar certificados antes del cambio
  • documentar comando/procedimiento exacto de rollback
