Inventario

Panorama general

El inventario disponible muestra APIs en us-east-1 y us-east-2, con distinta madurez operativa.
En us-east-1 están las APIs con mayor evidencia de uso y con los custom domains principales.
En us-east-2 hay APIs parcialmente configuradas, algunas sin stages activos.

APIs clave para la migración

1. apieconnectpro

Es la API más crítica del conjunto.

Características principales - Tipo: REST - Región principal: us-east-1 - API ID: zj7721vv78 - Stages: - econnect - test - valida - Dominio asociado: - api.econnectpro.mx (EDGE) - Perfil operativo: - alta centralidad funcional - múltiples rutas - múltiples dependencias Lambda - superficie pública amplia

2. apiusuarios

API importante para funciones de usuarios e integración.

Características principales - Tipo: REST - Región principal: us-east-1 - Stage visibles: - test - usuarios - Custom domain: no evidenciado - Auth principal: Cognito en la mayoría de métodos

3. api_socket

Canal de tiempo real.

Características principales - Tipo: WebSocket - Región principal: us-east-1 - Stages: - socket - test - Dominio asociado: - socket.econnectpro.mx (REGIONAL)

4. quicksight

API específica y de menor superficie.

Características principales - Tipo: REST - Región principal: us-east-1 - Stage: - inicial - Ruta principal observada: - POST /quick-dashboard

Clasificación por criticidad

Nivel APIs Motivo
Alta apieconnectpro API central, múltiples stages, múltiples Lambdas, custom domain
Media apiusuarios, api_socket, dev-auth-api Auth, usuarios y tiempo real
Baja / Media quicksight, api_procontrol uso puntual, reporting o pruebas

Hallazgos de arquitectura

  • En us-east-1 todas las APIs evidenciadas son públicas.
  • No hay evidencia de PRIVATE endpoint types.
  • No se observaron VPC endpoints asociados a API Gateway.
  • La presencia de una API EDGE y otra REGIONAL implica rutas de publicación diferentes para migración y rollback.

Qué debe quedar inventariado antes del cutover

Antes de mover tráfico a otra región, cada API debe tener documentado y validado:

  • tipo de API
  • API ID
  • stage destino
  • dominio asociado
  • método de autenticación
  • integraciones backend
  • CORS
  • binarios
  • logging
  • throttling
  • mecanismo de rollback

Decisión de migración por API

Migrar primero

  • quicksight
  • dev-auth-api
  • api_procontrol
    Estas APIs pueden servir como candidatos de ensayo por menor acoplamiento operativo.

Migrar en fase principal

  • apiusuarios
  • api_socket
  • apieconnectpro

No asumir listas para cutover

  • apieconnectpro en us-east-2
  • apiusuarios en us-east-2
    Aunque existen, la evidencia indica sin stages activos y por tanto no deben considerarse listas para producción.
