Inicio Otros Servicios

Resumen

El PDF contiene la parte más sólida de la evidencia en los servicios periféricos y de plataforma compartida: SES, WorkMail, SQS, EventBridge, S3, CloudFront, Route 53 y ELB. En conjunto, estos servicios describen cómo entra el tráfico, cómo se enruta, dónde vive el contenido, cómo se ejecutan automatizaciones y cómo se manejan las integraciones por correo.

Dominio funcional Servicios involucrados Evidencia principal
Entrada de tráfico Route 53, CloudFront, ELB, API Gateway Alias, CNAME, ALB DNS, execute-api, dominios públicos

Observabilidad de borde CloudFront, ELB invalidaciones, target health, listeners

Hallazgos transversales

  • us-east-1 es la región dominante. Allí viven ALB, EventBridge operativo, WorkMail, SES y la mayoría de los endpoints regionales.
  • CloudFront es global, pero oculta dependencias de origen regional.
  • S3 ya tiene piezas de replicación hacia mx-central-1, aunque no toda la cobertura está activa.
  • No se evidenció WAF en CloudFront, ALB ni API Gateway.
  • La trazabilidad es desigual: S3 y DNS tienen buen nivel; SQS, Lambda y API Gateway quedan parciales.

Recomendación de lectura

  1. route53.md y elb.md para entender entrada y dependencias de red.
  2. s3.md y cloudfront.md para contenido, replicación y edge.
  3. eventbridge.md, sqs.md y ses.md para procesos asíncronos y automatización.
  4. workmail.md para correo corporativo.
  5. migration-overview.md para el plan consolidado.

Riesgo central

El riesgo más importante no es un servicio aislado, sino la combinación de:

  • servicios regionales críticos en us-east-1,
  • DNS simple sin failover automatizado,
  • y gaps de evidencia en compute y APIs.

Eso significa que el inventario actual sirve para documentar y preparar la migración, pero no para cerrarla sin una validación adicional de los componentes no evidenciados directamente.
