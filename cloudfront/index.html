CloudFront

Resumen de qué hace en Econnect

CloudFront publica al menos los frontends de econnectpro.mx, www.econnectpro.mx y login.econnectpro.mx. La evidencia visible muestra 2 distribuciones, aunque Route 53 sugiere más aliases globales asociados a dominios CloudFront.

Inventario con tabla

Distribution ID Domain Aliases Origin Tipo de origen
EJEZ3D0CPREDW d3guam83da9hi9.cloudfront.net login.econnectpro.mx login.econnectpro.mx.s3-website-us-east-1.amazonaws.com Custom Origin (S3 website, HTTP-only)
E3U4W0AZLEF9D d2tu01v5fg90mp.cloudfront.net econnectpro.mx, www.econnectpro.mx econnectpro.mx.s3.amazonaws.com S3 origin

Control Estado

Geo restrictions no configuradas

Arquitectura / flujo

Route 53 -> CloudFront -> S3 origin / S3 website origin

Riesgos y gaps

  • login.econnectpro.mx usa S3 website endpoint HTTP-only.
  • TTL por defecto de 24h ralentiza rollback si no se invalida caché.
  • No se evidenció logging de CloudFront.
  • Existe inconsistencia entre DNS y el inventario de distribuciones visibles.

Runbook operativo

  1. Identificar distribución afectada.
  2. Revisar si el fallo es de origen, caché o DNS.
  3. Validar invalidations recientes.
  4. Revisar origen y política de forwarding.
  5. Si se cambia contenido, invalidar rutas necesarias.

Checklist de migración a mx-central-1

  1. Confirmar si el origen seguirá en S3 o cambiará.
  2. Migrar origen y certificado antes de tocar DNS.
  3. Reducir riesgo con invalidations planificadas.
  4. Evaluar mover a OAC/OAI moderno según origen.
  5. Validar contenido y headers desde el edge antes del cutover.

Cómo validar

aws cloudfront list-distributions
aws cloudfront list-invalidations --distribution-id E3U4W0AZLEF9D
aws cloudfront list-invalidations --distribution-id EJEZ3D0CPREDW

Cómo obtener la evidencia

aws cloudfront get-distribution --id E3U4W0AZLEF9D
aws cloudfront get-distribution-config --id E3U4W0AZLEF9D
aws cloudfront get-distribution --id EJEZ3D0CPREDW
aws wafv2 list-web-acls --scope CLOUDFRONT --region us-east-1
