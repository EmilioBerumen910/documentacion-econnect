Resumen de migración

Hallazgo central

La evidencia del PDF apunta a una plataforma con fuerte dependencia de us-east-1 en:

  • ALB,
  • EventBridge,
  • WorkMail,
  • SES,
  • varios endpoints DNS regionales,
  • y al menos una dependencia RDS visible por CNAME.

Secuencia recomendada

1. Cerrar gaps de inventario

Antes de mover producción, completar:

  • EC2 real,
  • RDS real,
  • Lambda completa,
  • API Gateway completa.

2. Asegurar entrada y publicación

  • Route 53
  • CloudFront
  • ELB
  • certificados ACM

3. Asegurar datos

  • S3 crítico y replicación
  • RDS y restore testing

4. Asegurar automatización

  • EventBridge
  • SQS
  • Lambda

5. Asegurar correo

  • SES
  • WorkMail

Riesgos más importantes

Riesgo Impacto
Dependencia de us-east-1 punto único de falla y complejidad de cutover
Inventario incompleto de compute/APIs migración ciega
Sin WAF evidenciado menor protección perimetral
Observabilidad parcial troubleshooting más lento
Replicación S3 no homogénea cobertura DR desigual

Criterio de Go/No-Go

No pasar a Go-Live sin:

  1. inventario completo de workloads,
  2. validación de RDS,
  3. pruebas de EventBridge/Lambda/SQS,
  4. revisión de DNS rollback,
  5. validación de frontends CloudFront/ALB,
  6. verificación de correo corporativo y programático.

Validación post-cutover

  • DNS resuelve a nuevos destinos.
  • CloudFront sirve contenido correcto.
  • ALB muestra targets healthy.
  • EventBridge dispara reglas críticas.
  • Colas SQS procesan sin backlog anómalo.
  • Correo SES y WorkMail funciona.
  • Aplicación conecta a la base correcta.

Comandos mínimos de validación

aws route53 list-resource-record-sets --hosted-zone-id Z1FARNXLLG1M1C
aws cloudfront list-distributions
aws elbv2 describe-target-health --target-group-arn <tg-arn> --region us-east-1
aws events list-rules --region us-east-1
aws sqs list-queues --region us-east-1
aws sesv2 get-account --region us-east-1
aws workmail list-organizations --region us-east-1
