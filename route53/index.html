Route 53

Resumen de qué hace en Econnect

Route 53 es el plano de control de publicación de Econnect. Desde el PDF se confirma que enruta frontends, APIs, login, SSO, correo, RDS y SFTP.

Arquitectura / flujo

DNS -> CloudFront / ALB / API Gateway / RDS / Transfer / SES inbound

Riesgos y gaps

  • No se evidenció weighted, failover, latency o geolocation routing.
  • No se evidenciaron Route 53 health checks propios.
  • El cutover parece depender de cambios manuales de records.
  • El inventario total de 19 hosted zones / 80+ records sigue parcial por paginación.

Runbook operativo

  1. Confirmar hosted zone y record afectado.
  2. Validar si el target es global (CloudFront) o regional (ALB/API Gateway/RDS/Transfer).
  3. Revisar EvaluateTargetHealth cuando aplique.
  4. Confirmar TTL y estrategia de rollback.

Checklist de migración a mx-central-1

  1. Clasificar records globales vs regionales.
  2. Preparar destinos equivalentes en región objetivo.
  3. Definir reducción temporal de TTL donde aplique.
  4. Documentar rollback record por record.
  5. Validar DNS después del cutover.

Cómo validar

aws route53 list-hosted-zones
aws route53 list-resource-record-sets --hosted-zone-id Z1FARNXLLG1M1C
aws route53 list-health-checks
