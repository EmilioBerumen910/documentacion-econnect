Plan de migración a mx-central-1

Objetivo

Replicar el servicio Lambda manteniendo los flujos: - API Gateway → Lambda (incluye authorizers) - EventBridge → Lambda (cron / reglas) - S3/SES/SQS → Lambda (event sources) - Networking (solo donde aplica: Lambdas en VPC)

Checklist de migración

1) Inventario y “source of truth”

  • Confirmar lista final de funciones por ambiente.
  • Identificar cómo se construye cada ZIP (pip/npm) y dónde vive el código (repo).
  • Para funciones Zappa: exportar configuración Zappa y reproducir deploy en destino.

2) Replicar configuración por función

  • Runtime y handler
  • Timeout / memory / ephemeral storage
  • Env vars
  • Roles IAM
  • Concurrency (reserved/provisioned) si aplica
  • Layers (si existen; son regionales)
  • VPC config (subnets/SGs) solo donde aplique

3) Replicar triggers e integraciones

  • API Gateway routes + stages + integrations
  • Lambda Authorizers
  • EventBridge rules (schedule expressions) + targets + DLQ
  • S3 notifications (bucket/prefix/suffix) + permisos
  • SES receipt rules + permisos
  • SQS event source mappings + batch size/visibility timeout + DLQ

4) Resolver cross-region

  • Evitar que API en una región apunte a Lambda en otra.
  • En destino, alinear API y Lambdas en mx-central-1.

5) Validación y cutover

  • Pruebas por flujo (API, crons, ingestión S3/SES, colas)
  • Canary o ruta paralela si es posible
  • Observabilidad/alarma lista antes de abrir tráfico
