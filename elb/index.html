Resumen de qué hace en Econnect

La capa ELB documentada es exclusivamente ALB y concentra la publicación regional de varios servicios en us-east-1.

Arquitectura / flujo

Route 53 -> ALB internet-facing -> target groups instance

Riesgos y gaps

  • Todos los ALB evidenciados están en us-east-1.
  • La mitad de los target groups visibles están unused.
  • No se evidencian access logs ni WAF.
  • No se evidenció entry point principal de forma concluyente.

Runbook operativo

  1. Confirmar dominio afectado y ALB asociado.
  2. Revisar listeners 80/443.
  3. Revisar target health y estado de la instancia.
  4. Si el target está unused, confirmar si el backend se retiró o el ALB quedó legado.
  5. Revisar certificados y expiración.

Checklist de migración a mx-central-1

  1. Inventariar ALB y target groups equivalentes.
  2. Replicar listeners y certificados.
  3. Replicar SGs, subnets y health checks.
  4. Validar backends sanos en región destino.
  5. Cambiar DNS cuando el destino esté listo.
  6. Mantener rollback al ALB original.

Cómo validar

aws elbv2 describe-load-balancers --region us-east-1
aws elbv2 describe-listeners --load-balancer-arn <alb-arn> --region us-east-1
aws elbv2 describe-target-groups --region us-east-1
aws elbv2 describe-target-health --target-group-arn <tg-arn> --region us-east-1

Cómo obtener la evidencia

aws elbv2 describe-load-balancer-attributes --load-balancer-arn <alb-arn> --region us-east-1
aws wafv2 list-web-acls --scope REGIONAL --region us-east-1
aws ec2 describe-security-groups --group-ids sg-fc671187 sg-9b3678e4 --region us-east-1
