F. Hallazgos de seguridad

  • Sin WAF evidenciado
  • Sin resource policies
  • Sin usage plans
  • Sin API keys requeridas
  • Auth inconsistente
  • WebSocket y HTTP API abiertos en algunos casos
  • stages sin throttling explícito

G. Hallazgos de observabilidad

  • sin access logs
  • execution logs OFF
  • CloudWatch Logs Role ARN no configurado para API Gateway
  • X-Ray parcial
  • sin alarmas de API Gateway
  • dashboards no utilizables

H. Hallazgos de configuración

  • no stage variables
  • integración fuerte con Lambda
  • uso de HTTP_PROXY a api.power-devel.com
  • CONVERT_TO_TEXT en rutas con binarios
  • binary media types habilitados
  • límites de payload de 10 MB
  • timeout efectivo ~29 s

I. Hallazgos de despliegue

  • IaC fragmentado:
  • CloudFormation
  • Serverless Framework
  • SAM
  • Zappa
  • Quick Starts
  • sin evidencia de Terraform
  • sin evidencia de CDK
  • sin CodePipeline
  • sin CodeBuild
  • sin evidencia de GitHub Actions o Jenkins
  • posible despliegue manual o con scripts ad-hoc

J. Notas de consistencia de datos

1. ID de apiusuarios

Aparece con dos variantes en la evidencia: - l4qndp97e6 - l4qndp976e

Debe confirmarse el valor exacto con inventario vivo antes de automatizar la migración.

2. Dominios vs runs inconsistentes

En una parte de la evidencia se reportan custom domains existentes, mientras que en otra ejecución se mencionan como “no encontrados”.
La documentación toma como referencia la evidencia más consistente y detallada, pero esta diferencia debe validarse en AWS antes del cambio.

3. Región destino no lista

La existencia de recursos en us-east-2 no implica preparación de producción.
Varias APIs carecen de stages activos o integraciones completas.
