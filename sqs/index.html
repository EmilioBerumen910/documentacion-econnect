SQS

Resumen de qué hace en Econnect

SQS soporta flujos documentales y de procesamiento asíncrono. El PDF evidencia una base relevante de colas en us-east-1 y us-east-2, pero la documentación sigue siendo parcial.

Arquitectura / flujo

Productor no evidenciado -> SQS -> Lambda (parcialmente evidenciado)

La nomenclatura sugiere flujos de:

  • carta porte,
  • pedimentos,
  • XML,
  • reportes,
  • estados,
  • acuses.

Riesgos y gaps

  • No se evidenció quién produce cada cola.
  • No se evidenció VisibilityTimeout, RedrivePolicy, cifrado ni tipo Standard/FIFO.
  • Dos colas visibles no tienen DLQ.
  • No existe mapa productor -> cola -> consumidor completo.

Runbook operativo

  1. Identificar la cola con backlog o fallo.
  2. Revisar si tiene consumer Lambda y cuántos mensajes en vuelo hay.
  3. Confirmar ausencia/presencia de DLQ.
  4. Revisar errores en la Lambda consumidora.
  5. Si no hay DLQ, tomar muestra de mensajes antes de reintentos prolongados.

Checklist de migración a mx-central-1

  1. Exportar atributos completos de las 47 colas.
  2. Clasificar Standard/FIFO y cifrado.
  3. Mapear productores y consumidores.
  4. Crear DLQ donde falte.
  5. Replicar colas en región objetivo.
  6. Reapuntar consumers y probar redrive.
  7. Validar backlog y procesamiento después del cutover.

Cómo validar

aws sqs list-queues --region us-east-1
aws sqs list-queues --region us-east-2
aws lambda list-event-source-mappings --region us-east-2 --function-name lambda-carta-porte-colas

Cómo obtener la evidencia

aws sqs get-queue-attributes --queue-url <queue-url> --attribute-names All --region us-east-1
aws lambda list-event-source-mappings --region us-east-1
aws cloudtrail lookup-events --lookup-attributes AttributeKey=EventName,AttributeValue=SendMessage --region us-east-1
