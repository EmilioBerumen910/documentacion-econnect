Seguridad y compliance

Fuente: assets/EC2-Documentacion-Econnect.pdf
Generado: 2026-03-03

Acceso a instancias

Session Manager (SSM)

En us-east-1 se usa SSM Session Manager como método principal (sin SSH/RDP):

Instancias “Managed / Online” con SSM: - Mongo-Reports (Amazon Linux) - sa31 c6 (Amazon Linux 2) - Windows (Windows Server 2019) - win_robots (Windows Server 2022)

En us-east-2 no hay instancias managed (no aplica Session Manager actualmente).

SSH / RDP (acceso tradicional)

  • SSH (22): restringido (allowlist /32) en varios SG (bien).
  • RDP (3389): mixto:
  • Hay allowlist /32 en algunos SG (bien).
  • Hallazgo crítico: el SG windows-server permite RDP desde 0.0.0.0/0 (abierto a Internet).

Auditoría de Session Manager (gaps)

Estado reportado: - Logging a S3/CloudWatch: NO configurado - KMS encryption: NO configurado - Idle timeout: default (no configurado)

Implicación: se puede operar sin SSH, pero falta trazabilidad/auditoría robusta de sesiones.

Controles de seguridad gestionados

AWS WAF

  • No habilitado (ni global CloudFront ni regional para ALB/API Gateway).
  • Implicación: no hay protección gestionada contra ataques web comunes (OWASP, bots, rate limiting).

AWS Shield

  • Shield Standard: ✅ (por defecto en CloudFront/Route53/ELB)
  • Shield Advanced: ❌ (no suscripción)

GuardDuty

  • us-east-1: ✅ habilitado (S3 Protection ✅, Malware Protection ✅)
  • us-east-2: ❌ no habilitado

IDS/IPS

  • AWS Network Firewall: ❌
  • GWLB + appliances: ❌
  • Terceros IDS/IPS: ❌ detectado
  • Controles presentes: ✅ Security Groups y ✅ NACLs (default VPCs)

Acciones recomendadas (prioridad)

  1. 🚨 Cerrar RDP 3389 desde 0.0.0.0/0 en windows-server (dejar allowlist o forzar SSM/VPN/bastion).
  2. Configurar Session Manager logging a CloudWatch Logs o S3 + KMS.
  3. Definir idle timeout y estandarizar configuración de SSM Agent.
  4. Evaluar habilitar WAF (CloudFront y/o ALBs) con managed rules + rate limiting.
  5. Habilitar GuardDuty en us-east-2 para cobertura completa (si hay workloads/colas allí).
